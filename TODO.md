## Known issues

- [ ] **Investigate `job cleanup: TerminateJobObject failed: The handle is invalid (0x80070006)`** — This message appears at the very end of the shutdown sequence and is currently **cosmetic only**: by the time `job.terminate_all()` runs in `main.rs::shutdown()`, every tracked process has already been terminated individually (in reverse start order) and MariaDB has been stopped gracefully via `mariadb-admin shutdown`, so there is nothing left for the job to kill — which is exactly why the error is visible in the logs but nothing is left running. The concern is that `ERROR_INVALID_HANDLE` suggests the job handle we hold may not be valid at that point (e.g. an earlier clone was dropped and its `CloseHandle` ran, or the handle was never validly configured), and if that is true then the job's `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` safety net would not fire for processes we never tracked directly — MariaDB, nginx and Apache started by Laragon — meaning a launcher that is killed from Task Manager could leave those behind. **Verify it:** start the stack with `ro_launcher.exe`, wait until all five ports are listening and the game is running, then kill `ro_launcher.exe` from Task Manager (End task) instead of closing the game, and check with Task Manager and `netstat -ano | findstr "3306 8888 8090 80"` whether `mysqld.exe`, `nginx.exe`, `httpd.exe`, `laragon.exe` and the four `*-server.exe` processes are gone. If any survive, the fix is in `src/job.rs` (verify the `HANDLE` is not closed by a dropped `Arc<HKEY>` clone and that `SetInformationJobObject` actually applied `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) rather than in the shutdown ordering.
